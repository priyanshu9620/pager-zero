# Problems hit & how we fixed them

Format: `P-n · date · problem · fix · lesson`. Interview-worthy ones also get a plain-English line in `kt/04-interview-faq.md`.

- **P-1 · 2026-11-09 · System Python is 3.9.** Fix: pin a newer interpreter per-project with uv. Lesson: never depend on macOS python.
- **P-2 · 2026-11-09 · `uv python install 3.12` failed: `~/.local` is owned by root** (some earlier `sudo` install). Fix: use Homebrew python 3.11 (`uv python pin 3.11`, `requires-python >=3.11`). Permanent fix if ever wanted: `sudo chown -R $(whoami) ~/.local`. Lesson: check `ls -ld ~/.local` before blaming the tool.
- **P-3 · 2026-11-09 · `uv add` failed "Expected a Python module at src/pager_zero/__init__.py"** because I deleted `src/` after `uv init --package`. Fix: recreate the package before adding deps (uv builds the project to lock).
- **P-4 · 2026-11-09 · zsh glob error on `psycopg[binary]`.** Quote extras in zsh: `"psycopg[binary]"`.
- **P-5 · 2026-11-09 · Pushing to the personal GitHub account from a laptop whose git is wired to the work account.** System gitconfig (`/Library/Developer/CommandLineTools/.../gitconfig`) sets `credential.helper=osxkeychain`, which only holds the work login; `gh` has both accounts but its credential helper did not resolve by URL username; `AUTHORIZATION: bearer` header is rejected by git-over-HTTPS. **Working one-off push:** `TOKEN=$(gh auth token --user priyanshu9620); git -c credential.helper= -c "http.https://github.com/.extraheader=AUTHORIZATION: basic $(printf 'x-access-token:%s' "$TOKEN" | base64)" push`. Nothing persisted. **Durable fix (user to run, Claude was denied creating SSH keys):** dedicated SSH key + `Host github-personal` alias — commands in PROGRESS 2026-11-09. Lesson: on a work laptop, isolate personal repos at the remote-URL level (SSH alias), not by switching global accounts.
- **P-6 · 2026-11-09 · Anthropic key valid but org has no credits** (`pz doctor --ping` → "Plans & Billing"). Not a code problem; add credits or set a Gemini/Groq key. Phase 1 needs no LLM.
- **P-8 · 2026-11-09 · Free-provider model names drift fast.** `gemini-2.5-flash` and `llama-3.3-70b-versatile` → `model_not_found` on 2026-11-09. Listed live catalogues: Gemini now serves 3.x (`gemini-3.8-flash` newest flash, `gemini-3.5-flash`, `-lite`); Groq serves `openai/gpt-oss-120b` (best tool-calling there), `openai/gpt-oss-20b`, `qwen/qwen3.8-27b`. Working picks: **Gemini `gemini-3.8-flash`**, **Groq `openai/gpt-oss-120b`**. Lesson: `pz doctor` should be able to list models per provider — added to Phase 8 polish. Also: **Gemini returns `AIMessage.content` as a list of blocks, Groq/Anthropic as str** — the agent must use `msg.text` (LangChain 1.x) / normalise, never assume `content` is a string.
- **P-9 · 2026-11-09 · One object implementing all Protocols → method-name collision** (`history` on CacheReader and FlagReader; ruff F811). Fix: unique names (`cache_history`, `flag_history`). Lesson: when one class satisfies many structural interfaces, the interfaces share a namespace.
- **P-10 · 2026-11-09 · `FastMCP.call_tool()` returns `(content_blocks, structured)` tuple**, and wraps non-dict results as `{"result": …}`. Test helper had to unwrap both. Lesson: check the SDK's actual return shape before asserting on it.
- **P-11 · 2026-11-09 · Groq rejects a `role:tool` message whose content is an empty list** (400 "content must be a string or ≥1 items"). Cause: `recent_deploys` returned `[]`, which the MCP adapter turned into an empty content-block list. Fix: list-returning tools return `{"count", "items", "note"}` (`_items()` in server.py). Lesson: never return a bare empty list from a tool.
- **P-12 · 2026-11-09 · Groq free tier = 8,000 tokens/minute**; one investigation turn is ~7k tokens → 429 on step 2. Mitigation: `max_retries=6` (SDK backoff) and compact JSON in prompts; but Groq free is simply too small for a 12-step agent. Use Gemini for free runs.
- **P-13 · 2026-11-09 · `gemini-3.8-flash` takes >90 s per tool-calling turn** (heavy hidden reasoning); `gemini-3.5-flash` 11 s (354 reasoning tokens); `gemini-3.5-flash-lite` 1.4 s. Measured with a 1-tool probe, `max_retries=0`. Lesson: time a tool-calling turn before choosing an agent model; "newest" ≠ "best for loops".
- **P-14 · 2026-11-09 · MCP adapter returns tool output as a list of content blocks, not a string.** Executor's `json.loads(out)` and the Rich renderer both broke. Fix: single `tool_output()` normaliser in graph.py used by `_call`, transcript, executor and renderer.
- **P-15 · 2026-11-09 · Read-only MCP process never saw the healed world.** Both sessions had their own in-memory World; the actions process saved to disk but the read process kept stale state, so verify reported "not recovered". Fix: read tools call `refresh()` (mtime check → reload) and the server clock is `now_fn=lambda: impl.world.now`. Lesson: when state is shared via a file, every reader must re-validate, and the "current time" must come from the state too.
- **P-16 · 2026-11-09 · `AIMessage.text` is a deprecated-callable shim in this langchain-core**; calling it spams warnings. Fix: `msg_text()` reads `.content` directly (str or text blocks).
- **P-17 · 2026-11-09 · psycopg3: `with conn:` CLOSES the connection on exit** (not just commits). My DDL ran inside `with conn, conn.cursor()` then the next statement hit "the connection is closed". Fix: cursor context only + explicit `conn.commit()`. Lesson: psycopg3 ≠ psycopg2 context-manager semantics.
- **P-18 · 2026-11-09 · Docker Desktop not running** → `docker info` fails. `open -a Docker` + ~20 s wait. Memory degrades to no-recall meanwhile (by design).
- **P-19 · 2026-11-09 · Bench run 1 miss: model proposed `set_flag(value="auto")`.** The action catalogue rendered my internal coercion kind `auto` as if it were a type. Fix: `_TYPE_HINT` renders "the flag's previous value (bool/int/str)". Lesson: anything you put in a prompt is a suggestion to the model — never leak internal enum names.
- **P-20 · 2026-11-09 · Bench run 1 miss: correct cause, wrong family label** (flag ttl→0 labelled `cache-eviction`). Taxonomy was ambiguous between trigger and symptom. Fix: DIAGNOSE prompt now says family = the trigger, with examples. Kept run-1 numbers as recorded; run 2 measures the fix.
- **P-21 · 2026-11-09 · Bench run 2: 19/20 crashed with `ExceptionGroup` at step 0.** Real cause: Gemini free **daily quota** for `gemini-3.5-flash-lite` exhausted (`429 RESOURCE_EXHAUSTED … exceeded your current quota`) after run 1 + live tests (~700k input tokens). The MCP client's anyio TaskGroup wrapped it. Fixes: bench now unwraps `ExceptionGroup`/`__cause__` to show the real error; results file of the failed run deleted (never a model result). Lesson: a 20-incident bench costs ~0.7M input tokens — budget free-tier quotas per model and per day; keep a second model's quota in reserve.
- **P-22 · 2026-11-09 · `gemini-3.5-flash` quota also exhausted after one incident** — Gemini AI Studio free quota appears to be shared/project-level and small (hundreds of requests/day), not per model as I assumed. Bench now aborts after 3 consecutive infrastructure errors and writes no results file. Free-tier reality: **one 20-incident bench per day per Google project**, so schedule runs, and keep Groq/other keys for live demos only. Resets daily (midnight Pacific ≈ 13:30 IST).
- **P-23 · 2026-11-09 · Live Redis adapter read `maxmemory 0` although the container had 64 MB.** A Homebrew `redis-server` on the laptop listens on 127.0.0.1:6379 and shadowed the Docker port mapping (same gotcha as the work-repo local e2e). Fix: compose maps redis to host **6380**; README/.env.example say so. Lesson: `lsof -iTCP:6379` before trusting localhost.
- **P-24 · 2026-11-09 · kafka-python 3.0.13 renamed the admin API**: `list_consumer_group_offsets` → `list_group_offsets({group: None})` returning `{group: {TopicPartition: OffsetAndMetadata}}`; `describe_consumer_groups` → `describe_groups([group])` returning `{group: {..., "members": [...]}}`. Found by smoke test against Redpanda, not by unit tests (fakes mirrored my wrong memory). Lesson: a fake client only proves you called what you *think* the API is — always run one real smoke.
- **P-25 · 2026-11-09 · `GET /incidents/{id}` 500: "Graph must have an entrypoint".** `current_state()` compiled an empty `StateGraph` just to call `aget_state`; langgraph 1.2 refuses. Latent in `pz incident show` too — never hit because the API test monkeypatched `current_state`. Fix: read `saver.aget_tuple(config).checkpoint["channel_values"]` directly and filter to `STATE_KEYS`; added a real SQLite round-trip test. Lesson: a mocked-out function is an untested function — give every seam one real test.
- **P-7 · 2026-11-09 · `.env` key not visible to provider SDKs.** pydantic-settings reads `.env` into the Settings object only; SDKs read `os.environ`. Fix: `load_dotenv()` in `config.py`.
- **P-26 · 2026-11-10 · First live incident investigated the SYNTHETIC world.** `pz serve` ran with `ADAPTER_BACKEND=live`, the webhook created a live incident, but the trace showed `checkout-api` on 2026-11-04 (= `bad-deploy #1`). Cause: the MCP stdio subprocess gets only the SDK's minimal default environment (HOME, PATH…) — `ADAPTER_BACKEND`, `REDIS_URL`, `LIVE_*` were silently dropped, the child read `.env` (synthetic) and ignored the `--alert-*` args. Fix: `runner._client` passes `env=dict(os.environ)`; regression test on `_server_env()` + live `_server_args`. Lesson: a child process that "works" on defaults is the most dangerous kind of misconfiguration — assert the backend in the trace (`incident_context` → services list) when testing a new backend.
- **P-27 · 2026-11-10 · Alertmanager could not reach `pz serve`.** Default `pz serve` binds 127.0.0.1; containers reach the host via `host.docker.internal`, which needs 0.0.0.0. Fix: `make demo-serve` and the `pz demo up` hint use `--host 0.0.0.0`.
- **P-28 · 2026-11-10 · Exporter's `instance="offer-cache"` label was overwritten** by Prometheus with the scrape target (`exporter:9100`), so `RedisCache.cache_history` (queries `{instance=name}`) found nothing. Fix: `honor_labels: true` on the exporter job. Also: ratio recording rules (`http_error_rate`, `dependency_error_rate`) produced NO series while nothing had failed yet (numerator missing) — the agent would see "no data" instead of 0. Fix: pre-create the error-labelled counters at 0 in shop-api.

- **P-29 · 2026-11-10 · Live incident #2 died mid-investigation with `ExceptionGroup`** — real cause: Gemini 429, both `gemini-3.1-flash-lite` and `gemini-3.5-flash-lite` at their **500 requests/day** quota (`quotaValue: 500`, per model, resets ~13:30 IST). The API handler had flattened the group to its useless outer message. Fix: `pager_zero/errors.py` (`root_cause`/`describe`/`full_trace`) shared by API + bench; the API now writes `.pz/incidents/<id>/error.txt` with the full traceback. Lesson: the free-tier unit is *requests*, not tokens — an investigation is ~10–15 requests, a 20-incident bench ~250; two benches a day is the ceiling per model.
- **P-30 · 2026-11-10 · Groq free tier also has a 200k tokens/DAY cap** (`openai/gpt-oss-120b`, TPD) — hit on live incident #3 after one tool-calling turn (198k already used by earlier tests). With Gemini's 500 req/day/model this means: on a heavy test day, **all free providers can be gone by early afternoon**. Mitigations to consider: `pz doctor --quota` that pings each configured provider and reports remaining/reset; keep one provider untouched for demos; for benches prefer late evening IST (Gemini resets 13:30 IST, Groq rolling 24 h).
- **P-31 · 2026-11-10 · Live `verify` watched 300 s and never saw the recovery although Prometheus showed p99 back to 24 ms within a minute of the rollback.** `build_server.now()` falls back to `incident["now"]`, which `live_incident()` stamped once at MCP-server start → every `since(minutes)` window ended at server start; the agent (and verify) were reading a frozen snapshot of the system. Fix: live incidents carry no `now`; the server uses the wall clock; regression test asserts `incident_context.now` ≈ now. Lesson: the synthetic world *needs* a frozen clock (`now_fn`), the live world must never have one — a shared code path with a "sensible fallback" hid the difference. Round 5 otherwise was correct end-to-end: Gemini 3.5-flash-lite diagnosed `bad-deploy v1.5.0` in 50 s / 8 tool calls, proposed `rollback_deploy(shop-api, v1.4.0)`, the real container was rolled back, and the real p99 recovered — only the verdict was wrong.
- **P-32 · 2026-11-10 · UI showed an empty pane for every live incident.** `resultSummary`'s last fallback did `'last' in d[keys[0]]` — for the new `get_diff` dict the first value is a string, `in` throws, and the exception escaped `render()`, so the whole detail pane stayed blank with no visible error. Fix: per-summary try/catch (one odd tool output can only lose its own summary), object check before `in`, dedicated diff summary. Found with a node probe that runs the page's JS against the live API for several incidents (scratchpad `ui_probe.js`) — worth keeping as a test idea. Lesson: a renderer that builds one big string must isolate failures per row.
